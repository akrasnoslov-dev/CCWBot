# Оценка уведомлений CCWBot: порядок действий

Оценщиков двое: ты — Reviewer A, твой друг — Reviewer B.
В файлах 200 реальных рыночных ситуаций (BTC, ETH, GRAM, SOL).
Все оценки независимы: не обсуждайте случаи, пока оба не закончат первый этап.

ЭТАП 1 — определить, нужно ли уведомление.
Открыть reviewer_A_phase1_significance.csv (или B для друга).
В столбце warrant (alert/no_alert/ambiguous) поставить:
- alert — движение рынка действительно заслуживает уведомления;
- no_alert — это обычный рыночный шум;
- ambiguous — данных недостаточно или случай пограничный.
По возможности написать короткую причину в warrant_reason.
Оценивайте ситуацию с учётом графика, окна анализа, истории и новостей.
Новость сама по себе не повод отправлять Event Alert. Жёстких порогов % нет.
Решение бота скрыто. Не изменять case_id и исходные данные.

ЭТАП 2 — только когда ОБА полностью закончили и сохранили ЭТАП 1.
Открыть reviewer_A_phase2_final_message.csv (или B).
Здесь 72 реально отправленных текста. Для каждого поставить yes/no:
- useful — добавляет ли текст полезное и проверяемое объяснение или наблюдение?
- factual — нет ли выдуманных фактов, чисел, причин и неверного направления?
В reason_if_no пояснить любой ответ no.

Сохранить CSV в UTF-8. Вернуть оба заполненных файла отдельно.
Оригинальные решения и технический набор v2_private_sanitized.json
не показывать оценщикам до сдачи оценок.

Эта выборка намеренно сбалансирована, но не представляет естественную
частоту уведомлений в production. Точность и полнота не измерены до оценки.
Хранить пакеты приватно. Не публиковать данные на GitHub.
